# v0.2 源码分发与隔离检查

`MANIFEST.in` 将维护包源码、`scripts/` 中的恢复/复现工具、双语 README、许可证与安全/贡献说明、计划、协议、架构、公开研究示例和结构测试纳入 sdist。`experiments/`、`artifacts/`、`private/`、运行状态、虚拟环境及凭据文件均不在源码包内。`.env.example` 只用于说明配置名称。

源码 sdist 与 wheel 不承载完整实验原始证据。需要恢复原始路径时，另取完整证据包，先按[证据包说明](v0.2-evidence-package.md)核对 SHA256，再使用[独立复现入口](v0.2-reproduction.md)。安装包可用、源码测试通过、证据包完整及实验效果是不同的检查结论。

## 构建检查包

在仓库根目录执行：

```sh
uv build --out-dir private/v02-packaging-check
```

该目录仅供本地检查，不是最终 release。检查 `.tar.gz` 应含 `scripts/reproduce_continual.py`、`scripts/resume_continual.py`、`scripts/resume_readout.py`、`scripts/package_v02_evidence.py` 及完整 `src/moltweave/*.py`，且不含上述排除目录。最终发布应从确定的源码版本重新构建并另行记录校验值。

wheel 提供 `moltweave` 包和 CLI；源码脚本、文档和测试由 sdist 提供，不要求安装进 site-packages。不要把 wheel 缺少仓库级恢复脚本误认为脚本已丢失，也不要把 sdist 的存在当成大体积原始证据已经分发。

## 全新副本的两类验证

先分别准备一个未使用过的源码副本和安装包环境。下面只验证离线行为，不配置凭据，不运行模型。实际构建文件名以输出为准。

**安装包 CLI：** 在独立虚拟环境中非 editable 安装 wheel，从仓库外的空目录启动一个全新解释器，清除外部 `PYTHONPATH` 后运行 `moltweave --help`、`python -m moltweave --help`，并记录 `moltweave.__file__`，确认导入位置在该环境的 site-packages。这验证安装包及入口，不验证仓库源码的恢复合同。

**源码 suite：** 在另一个全新解释器中，从副本根目录启动，首次导入前显式指定源码路径：

```sh
PYTHONPATH=src python3 -W error::ResourceWarning \
  -m unittest discover -s tests -v
```

测试中的模型调用由结构 fixture/mock 替代；此命令不是正式模型效果实验。源码 suite 也可用专门环境的 editable 安装运行，但必须从首次导入起就绑定同一副本的 `src/`。在抽出的 sdist 中同样保留了源码和测试，原始实验检查仍须单独取得证据。

`scripts/resume_readout.py:maintained_host` 会核对仓库 `src/moltweave` 的冻结内容，并要求导入模块的 `__file__` 正好指向该位置。若同一进程已从非 editable 安装包导入 `moltweave`，事后修改 `sys.path` 不会替换 `sys.modules` 中的缓存；随后运行源码 suite 可能被 guard 拒绝。这是来源隔离生效，不应删除缓存、改写模块路径或放宽 guard 来制造通过。使用不同的新进程/环境，分别报告安装包 CLI 与源码 suite 的实际回执。
