# v0.2 provider 402 中断后的恢复附录

本附录在独立 readout 之前加入，处理 `continual-v02-main` 的 provider HTTP 402 余额中断。原始 summary 记录 20 条演化 lane 中断、10 条 fixed-mechanism lane 已完成 20 轮。单独的 `interruption-diagnosis.json` 是停机后的诊断，不改写原异常或原模型回执。

恢复使用新增的外层 `scripts/resume_continual.py`，不修改 manifest 或冻结九份核心源码。这属于明确记录的工程恢复，不是自动 RSI 改进，也不是未间断、逐次相同或 exactly-once 的重现。工具的实现与结构测试未调用真实模型；正式恢复是否启动、完成或再次中断，必须以新 ledger 和 summary 为准。

## 提交边界与测量处理

只有 `versions/g(r+1).json` 写成且与 round r 的 transition、观察记忆和父子版本链一致，round r 才视为已提交。已提交的 checkpoint 和轮次保留原始字节，不重新调用模型。完成全部轮次的 fixed-mechanism lane 会被跳过。

尚未提交的 round 即使已经出现有效回答、候选分数、低分、高分或部分 probe，也一律整轮归档后重放。不会根据这些部分分数选择保留哪次，不把它们传入恢复后的 history／M／P／记忆，也不把它们算成正式 committed 测量。其调用成本仍应统计。恢复读取最后一次提交的 M、P、持久记忆和 history；未落入 checkpoint 的 `rejected` 父候选按已完成 `mechanism-search.json` 中冻结 host 的同一规则重建。

外层直接提取经 manifest 校验的 `run_lane` 原始 `for r in range(rounds)` AST，保留循环 body，只把起点改为已提交轮数。执行命名空间由 checkpoint 初始化。这个 Python 执行入口只接受审计过的冻结 host AST，不接受模型生成的代码、Trace 指令或候选 IR 来修改恢复程序。

## 离线计划与显式执行

```sh
python3 scripts/resume_continual.py --check \
  --experiment experiments/continual-v02-main
```

默认也是 `--check`：读取来源、summary、checkpoint、父子链和 partial 目录，并在临时包中加载冻结的纯基线／验证器，检查 g0 确为初始 M/P、空记忆、空 history，逐 checkpoint 验证 M/P/记忆及 rejected。它输出完成／待恢复 lane 与下一轮编号，不导入模型客户端、不调用 API、不改原实验；路径父级符号链接会被拒绝。

当前中止原因优先来自 `summary.errors` 引用的 failed receipt：核对原 receipt ID、失败状态及其 stream／arm／未提交 round，再记录回执中的实际 `error_type`、路径、原字节 SHA256 和各物理尝试类型。异常文本中出现 JSONDecodeError 不足以替代回执核对。后续恢复没有可核验的新回执时原因保持 unknown；原始 `interruption-diagnosis.json` 的 402 只在 `historical_interruption_reasons` 单列，不能冒充本次原因。首次运行的数字 HTTP 诊断仍保留其原始适用范围。冻结客户端只记录粗粒度 HTTPError 时，不从历史 402 推断新请求也返回 402。

充值确认并核对原 requested model、HTTPS endpoint 与成对凭据后，操作者才显式执行：

```sh
python3 scripts/resume_continual.py --execute \
  --experiment experiments/continual-v02-main \
  --concurrency 32
```

这里会产生真实模型调用及费用。无网络 preflight 使用冻结 `ModelClient` 检查原模型、地址、HTTPS／无重定向／无环境代理，以及冻结源码和任务分区；它不能证明余额足够。恢复工具不会自动充值或因为 `--check` 成功就认为 provider 已恢复。

## 归档与溯源

每次恢复使用唯一 `resume-history/ID/`：

- `plan.json` 在移动任何 partial 前落盘，包含 checkpoint hash、来源 digest、原 summary hash、外层 driver／安全 guard hash、恢复理由和 `exactly_once=false`。启动后不能修改这两个脚本；worker 会核对 guard hash。
- `original-summary.json`、历史 lane 元数据副本和 `discarded-partial-rounds/` 保留之前的运行与测量。原 `ABORTED.json` 也继续留在原 lane 路径，表示历史失败；恢复后的当前状态由新 summary／ledger 解释。
- `previous-model-calls.json` 记录旧回执文件的原始 SHA256；结束后逐一核对旧文件仍在且字节未变。
- `archive-completed.json` 记录 partial 原路径、归档路径、从哪个 checkpoint 重放，以及这些旧部分分数没有用于选择。
- `worker-started.json` 与控制器锁防止同一 ledger 重复执行；新异常、`worker-result.json` 和 `completion.json` 继续留存。

新调用写入 `model-calls/resume-ID/` 的全新子目录，不覆盖旧 UUID 文件。成本分析必须递归汇总原调用和所有恢复子目录，检查重复 receipt ID；归档 partial 的成本也不能删掉。恢复结束才在保全旧 summary 后更新当前 `summary.json`，来源 manifest、冻结源码和停机诊断不变。

如果再次中断，新 partial 和新调用继续留存。下一次必须创建新的 ledger，从新的最后已提交 checkpoint 重新规划。独立 readout 一旦开始，本工具拒绝恢复演化。控制器异常终止留下锁时，应先核实没有恢复进程仍在运行，再由操作者处理 stale lock；工具不会自行抢占它。

## 独立 readout 的恢复

所有演化 lane 完成并封存各代 M/P/记忆后，使用独立的 `scripts/resume_readout.py`。它先校验 manifest、冻结来源、完整版本链和任务分区，并要求当前维护包中的九份核心源码与原实验 digest 一致。它不会恢复演化，也不会将 readout 分数送回候选选择。

默认只做离线检查，不调用模型：

```sh
python3 scripts/resume_readout.py --experiment experiments/continual-v02-main
```

也可显式加 `--check`。确认后，仅用 `--execute` 发起尚缺的真实测量；模型及 endpoint 必须与原 manifest 一致，安全传输配置也须匹配：

```sh
python3 scripts/resume_readout.py --experiment experiments/continual-v02-main \
  --execute --concurrency 32
```

复用边界以完整、验证通过的文件为单位，统一适用于高分、低分及其他有效结果：

- 一个普通版本的 `independent/seed/arm/gN.json` 必须同时包含完整 acceptance 与 transfer。终代还必须同时包含 no_memory 和 wide_context_baseline。完整文件会用保存的模型输出在冻结 host 中离线重放，核对任务顺序、机制、记忆写入、评分和报告，再按原字节复用，无需重新采样。
- 如果版本文件只包含部分 split，其中已完成的 split 也不会单独拼接到新结果中。原 partial 文件移入本次 ledger 的 `preserved-partial/`，该版本的全部 split 作为一个测量单位重跑。不存在或尚未写成最终文件的版本也整版本执行；先前调用回执继续保留。
- 每个 seed 的完整 `policy-audit-inputs/seed.json` 单独验证、复用；完整的 `policy-audits/seed/gN.json` 也单独验证、复用。缺少或不完整的 input、audit 按各自整个单位重跑。若已存在 audit 却缺少它所绑定的公共 input，工具拒绝执行，不能另造输入来解释旧 audit。
- 结构完整却无法通过来源、绑定或离线重放验证的文件属于完整性错误，工具停止，不将其当作可自动重试的低分。已经存在的 `independent.json` 只有在全部必需报告齐全且摘要完全一致时才可复用，不覆盖或挑选另一份摘要。

每次真实执行新增 `readout-resume/ID/ledger.json`，记录来源 digest、工具 hash、完整结果复用、partial 归档、测量单位起止及失败；新调用只写入 `model-calls/readout-resume-ID/`。最终报告通过独占发布创建，不能覆盖已有文件。中断前已完整提交且通过验证的单位继续复用，未完成单位下一次整体重跑，所有旧调用成本仍计入。这同样不承诺 exactly-once，也不构成按结果重试。

readout 执行锁使用 Linux/macOS 的 `fcntl.flock`，仅这些平台的恢复执行路径已实现；Windows 的 readout 恢复执行尚未实现或测试，这不等于整个项目的其他运行路径不支持 Windows。锁文件 `.readout-resume.lock` 会保留，进程退出或被终止后由操作系统释放锁；后续执行重新竞争该文件的锁，不能通过删除文件来绕过仍在运行的进程。离线 `--check` 不获取执行锁，因此并发运行期间看到的检查结果仅是当时快照，正式执行会在取得锁后重新校验。

## 声明范围

这是一项有公开恢复附录的连续实验，不能描述为从开始到结束未间断运行。重放一个未提交 round 可能产生不同提案和分数；采样、provider 变化与恢复调度都可能影响轨迹。恢复只隔离并记录这些影响，不承诺它们不存在。只有新 committed 结果和后续独立 readout 才能支持效果结论。

结构测试使用合成 checkpoint、模拟子进程和可读 AST fixture；它们证明恢复边界及证据保全逻辑，不能替代真实充值后的续跑或模型效果验证。
