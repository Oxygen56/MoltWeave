# v0.2 continuous-memory and future-search protocol

This contract is authored before the formal 20-round, 10-stream readout. An experiment manifest freezes its exact host sources, requested model/endpoint, task sequences and frozen descendant states. Engineering preflights are retained separately and never pooled into formal effects.

## What changes

`M` contains executable memory read/write scoring, retrieval and tool scoring, retry decisions, context allocation and the task prompt. `P` contains a diagnosis prompt, candidate-generation prompt, action-selection expression and allowed improvement operators. Operators are bounded rewrite, contrastive alternatives and coordinated multi-module changes. P can select an actual host-bound parent candidate. It cannot change source authority, consent, permissions, validation, scoring or acceptance.

There is no task-family-to-module table in this engine. A real model proposes competing explanations from sealed execution traces, cites checked JSON Pointers and receives actual candidate execution feedback. References prove provenance, not causal correctness. A changed program hash proves different serialized code; it does not prove semantic or behavioral difference. Actual loaded decisions and outcomes remain separate evidence. The contrastive operator generates and validates two alternatives; only its selected alternative is executed. The executed candidate and baseline are measured; model confidence or self-reported success never establishes benefit.

## Persistent memory and transient execution

Every task starts with a fresh model request and fresh tool-attempt state. Factual memory, M, P and search history persist across tasks and rounds within one arm/stream. Each stream revisits four entities over 20 rounds; source revisions increase across visits. Previous-round and three-round delayed recalls test retention. Business source-of-truth policies can change, so a verified replica fact is not automatically the approved answer.

The task model answers first. A separate real extraction call receives only newly visible authorized observations, never the hidden expected answer, scoring feedback or the task model's guesses. The host verifies exact `source_id/entity/key/value` against those observations. M's write program decides whether to retain a verified proposal. Revisions are comparable within a source lineage; cross-source revisions cannot overwrite one another. Every write, correction, quarantine, read and revocation has provenance. Owner/tenant filtering precedes ranking.

Early preflights exposed conflicting answer/writer output contracts; their empty-memory failures remain archived. The formal host separates those calls and starts all arms from the same functioning memory baseline. The engineering correction is not an RSI improvement.

## Three continuous arms

Ten predeclared synthetic streams use seeds 101–110. Each has 20 rounds and three arms:

1. **fixed_mechanism:** reasonable authority/entity/recency scoring, factual writing and retry baseline; experience accumulates normally, M/P remain fixed.
2. **fixed_p:** the same initial M/P; two actual mechanism search opportunities per round; P remains fixed.
3. **joint:** the same initial M/P and mechanism search opportunities; P can be promoted after actual paired future searches.

Both evolving arms perform policy proposals and shadow paired probes. The fixed-P arm records those results without adopting P. This gives both arms the same declared opportunity rules; invalid candidates, repairs and actual physical calls can still differ and are reported. No equal-token or equal-compute advantage is assumed.

## P promotion and state isolation

After an M search, old P and proposed P fork from exactly the same M, factual-memory snapshot, observations and history. Each gets one candidate-search slot with the same fixed engine, model and task sequences. Prompt/operator/parent-selection differences are the P treatment. Neither fork sees the other's results; fork memories and descendant mechanisms never merge into the main trajectory.

Each candidate is actually executed on development/protection tasks. The selected descendant M is then measured on fresh **meta-development future** tasks. P promotion requires valid executed searches on both sides, different selected mechanisms, a strict future gain and no protection regression. Syntax-invalid or no-action forks retain their fallback readouts, but the valid-search effect is unknown and cannot promote P. These repeated meta-development results are optimization data.

“Best rejected” means the measured rejected candidate from the most recent search round that had one, ranked by protection eligibility, development successes and protection successes. If a round has none, the previous rejected parent remains available. It is not a global optimum across different task sequences.

## Independent measurement

All 21 versions of all three arms are sealed before any final readout. The host verifies source, model/endpoint, exact task hashes, version-state hashes and parent/descendant M/P chains.

- **Mechanism primary:** every frozen M starts with empty factual memory and executes the same new five-round event sequence (rounds 0–4, including cross-visit revision and delayed recall). This separates a better write/read mechanism from carrying more accumulated answers.
- **Namespace transfer:** a new source/entity/owner namespace executes the predeclared round-7 sequence. Generation grammar is shared. This is not a new real-world business-system benchmark.
- **Memory ablation:** terminal M executes the same primary sequence with factual reads/writes disabled.
- **Context-width control:** a fixed baseline M with read/retrieval top-k=6 executes the same primary sequence. Gains from simply supplying more evidence must remain visible.
- **Independent P audit:** after evolution, each seed seals one common new audit-observation snapshot. P0 and each checkpoint P execute fresh future searches from that same state: baseline M, the fixed-P terminal memory/history, and that seed's one newly sealed observation episode. Only the current M parent is supplied in this audit. This measures policy transfer to a common search state, not a continuation from terminal joint M. Checkpoints include the terminal P; final question answering is not substituted for P execution. g0 compares P0 to itself and exposes sampling variation. These audits never select a policy or resume evolution.

The predeclared main mechanism endpoint is terminal joint minus terminal fixed-P, paired by stream. The policy endpoint is terminal P versus P0 in independent future-search audits, conditional on both actual searches being valid and executed. This primary execution contrast includes streams whose terminal P is still P0; the valid-and-actually-distinct-P subset is explanatory and cannot replace it. Invalid attempts keep unknown search effects. The separate all-attempt fallback outcome contrast is an operational estimand, not evidence of a valid changed-policy effect. Report the exact included/excluded streams and denominators for each; do not choose the most favorable contrast. The g0 same-P comparison calibrates variation in the complete search/write/answer pipeline. It is never subtracted after the fact, and a positive same-P contrast is never labeled P-evolution benefit. All intermediate versions remain visible; the final readout cannot choose the best generation. Valid and invalid search-pair counts are explicit. Operational fallback outcomes are separate from valid-search effects.

## Uncertainty and failures

The primary statistical unit is the stream, not an individual question. Report paired differences, descriptive bootstrap intervals and exact sign-permutation results with all ten predefined streams. Ten synthetic namespaces do not establish general real-world robustness. Conditional subsets can contain fewer than ten streams. Checkpoint, transfer and ablation intervals/p-values are descriptive; no favorable checkpoint or significant secondary result replaces the terminal primary endpoint. Requested temperature zero is not deterministic, and provider aliases do not guarantee immutable backend weights; returned identities and physical attempts remain in receipts.

Illegal proposals consume search opportunities and retain unknown effects. Each request block has at most three physical attempts; model JSON syntax/shape errors may receive actual model repair feedback with original content and per-attempt request hashes retained. The continuous engine allows one further measurement-only request block after declared transient/JSON failures (at most six physical requests before a usable object). Valid low scores and invalid IR are never retried to obtain a better result; fixed mechanism-approval and transport-policy denials cannot be bypassed. The frozen HTTP client records provider failures coarsely as HTTPError and may retry them within these bounds, including non-transient provider errors. A separate diagnostic records the observed HTTP status; this host does not implement status-specific HTTP retry filtering. Model repair is requested to preserve the proposal; semantic equivalence is not guaranteed, so the normal validator and experiment gates still apply.

Exhausted API/parsing or execution-measurement failures abort the affected run and preserve original receipts; they are not recoded as mechanism failure scores. Regressing, rejected and flat generations remain public. If P does not outperform fixed P, that is the released conclusion.
