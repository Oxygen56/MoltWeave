# Project decisions

## Name

MoltWeave combines repeated molting with weaving new experience and research into future mechanisms. A preliminary public search found no clear same-named agent repository; this is not a trademark clearance. The earlier working name MoltLoop overlaps an unrelated token, so the public project and Python namespace were renamed before the formal experiment. Historical aborted preflight receipts retain the original names.

## Evidence before presentation

The public story follows actual generated descendants and independent readouts. No target improvement percentage, positive result or continuous monotonic curve is assumed. A failed transition remains visible. Research discovery, structural guardrail tests, actual mechanism evolution, held-out effect and public publication each have separate receipts.

## Bounded executable programs

The fixed interpreter supports compositions and conditionals; the generated program actually determines rankings, retry decisions and improvement branches. This is a deliberate execution boundary agreed before implementation. Permission changes and sensitive behavior require owner review; the system cannot lower its own scoring or approve itself.

## Two preflight corrections

The initial provider call used an Anthropic compatibility path with a chat-completions payload and returned 404; the adapter now selects the compatible provider path. Two paired preflights then exposed output truncation because provider thinking is enabled by default. Their raw runs are retained as aborted infrastructure experiments, not positive or negative mechanism results.

The formal protocol pins thinking mode, retains every physical retry, rejects measurement-unavailable batches, freezes host/source/data hashes, validates the complete descendant chain before final readout, and states the exact answer contract in H0. No final/transfer model readout occurred during these repairs.
