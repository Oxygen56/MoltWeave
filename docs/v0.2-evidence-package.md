# v0.2 完整原始证据包

`scripts/package_v02_evidence.py` 将仓库下选定的 `experiments/continual-*` 目录完整打成一个离线证据包。它不调用模型、不联网、不发布、不删除原文件，也不改变原始文件字节。包括工程预检、失败与中止记录；不删除可再生 HTML，不从原始证据中挑选有利结果。

**只在所有正式演化、续跑和独立读出都停止写入后生成最终包。** 源树变化会使打包拒绝，但这不能代替先停止 writer。若之后继续运行，应在最终完成后使用新文件名重新打包；早期包及校验值不代表最终证据。本说明和脚本交付本身不代表正式证据已经被打包或校验。

## 运行

脚本只依赖 Python 3.11+ 标准库，与 `src/` 包无关。下面以仓库根为当前目录；`--repo-root` 和 `--output` 都显式提供。相对输出路径相对于 repo-root，且必须位于已忽略的 `dist/` 内。

```bash
# 可选预检：逐文件检查与计算 SHA256，不创建压缩包。
python3 scripts/package_v02_evidence.py \
  --repo-root "$PWD" --check

# 最终打包；仅在所有写入停止后运行。
python3 scripts/package_v02_evidence.py \
  --repo-root "$PWD" \
  --output dist/moltweave-v02-complete-evidence.tar.gz

# 独立复核，不解压，也不需要仓库或模型凭据。
python3 scripts/package_v02_evidence.py \
  --verify dist/moltweave-v02-complete-evidence.tar.gz
```

默认选择 `experiments/` 的全部直接 `continual-*` 子目录。若只检查一个明确目录，可重复使用 `--run`；它只接受直接目录名，不能传路径或 `../`：

```bash
python3 scripts/package_v02_evidence.py \
  --repo-root "$PWD" --check \
  --run continual-v02-main
```

完整发布包应采用默认全选，不把某个子目录包误称为全部证据。`private/`、`.venv/` 和其他实验目录不在选择范围内。选中目录内部所有普通文件及空目录都会保留，遇到符号链接、特殊文件或越界路径则整次拒绝。原始文件中的失败、余额不足或其他 provider 错误都照原字节保留。

## 三个输出文件

| 文件 | 内容 |
|---|---|
| `moltweave-v02-complete-evidence.tar.gz` | 全部选中目录，路径仍为 `experiments/continual-…/…`；另含包内元数据目录 |
| 同名后缀 `.manifest.jsonl` | 每个原始文件的 repo-relative 路径、原字节数、原字节 SHA256；目录条目也列出，便于核对空目录 |
| 同名后缀 `.sha256` | 压缩包自身的独立 SHA256，采用标准 `hash  filename` 格式 |

包内 `__moltweave_evidence__/package.json` 记录选择范围、计数和清单哈希，`__moltweave_evidence__/manifest.jsonl` 与外置清单字节一致。这里的文件 SHA256 对原始字节计算，与项目内部对规范化 JSON 计算的程序/状态哈希是不同层次的校验。

输出及任何同名 sidecar 已存在时都拒绝覆盖。生成时先写 `dist/` 中的临时目录，完成检查后以不覆盖方式发布三个文件；不会借打包清理源目录。输入文件内容、大小、inode、mtime/ctime 或目录集合在扫描与压缩期间发生变化，会拒绝发布。默认全选时，新增或移除一个 `continual-*` 目录也会拒绝，避免漏掉打包过程中刚出现的运行目录。

## 密钥检查

打包前逐块扫描全部选中源文件及相对路径：

- 当前进程环境中以 `API_KEY`、`ACCESS_TOKEN`、`AUTH_TOKEN`、`CLIENT_SECRET`、`PASSWORD`、`SECRET_KEY`、`PRIVATE_KEY`、`TOKEN` 结尾的非空配置值，做精确检查；还检查它们的常见 JSON、Base64 和 URL 编码形式。
- 对明显的 provider key、Bearer 凭据、私钥头等做保守格式检查。
- 分块间保留有限重叠，避免密钥恰好跨块漏检。遇到匹配则拒绝，不打印值或文本摘录；只有相对路径自身已通过扫描时，内容错误才附该文件路径帮助定位。

脚本不自动读取 `.env`，也不会在日志中输出配置值或其指纹。应在与正式运行相同的凭据环境下执行，并检查返回的 `configured_exact_secret_count`。该计数为 0 意味着没有当前配置值可作精确比较，不代表检查过全部历史凭据。

需要强制检查额外配置时，只传**环境变量名**；该变量不存在或为空就拒绝，不把秘密值写进命令行：

```bash
python3 scripts/package_v02_evidence.py \
  --repo-root "$PWD" --check --secret-env MOLTWEAVE_API_KEY
```

内容中的 `synthetic=true` 或“这是测试密钥”等文字不能免除检查；当前没有文档可控制的白名单。格式检查会保守拒绝看起来像密钥的字符串，因此拒绝不等于已经联网证明该密钥有效。它也不是任意未知凭据格式都不会泄漏的保证。发现匹配时先检查对应原始记录与配置，再决定处置；脚本不会擅自改写或脱敏原始证据后继续打包。

## 独立校验与恢复原路径

`--verify` 首先核对独立 `.sha256`，然后流式读取包内清单和每个文件，校验原字节 SHA256、大小、路径、目录、成员唯一性及固定 tar 元数据。外置清单存在时还要与包内清单一致；可通过 `--manifest`、`--sha256-file` 显式指定下载后的 sidecar 位置。独立压缩包校验文件必须存在。

校验操作不执行包内程序、不调用模型，也不提取任何路径。将三个文件一起下载，在可信来源取得校验值后运行：

```bash
python3 scripts/package_v02_evidence.py \
  --verify /path/to/moltweave-v02-complete-evidence.tar.gz
```

通过校验后，在需要恢复的**仓库根**提取即可恢复原实验路径：

```bash
tar -xzf /path/to/moltweave-v02-complete-evidence.tar.gz \
  -C /path/to/MoltWeave
```

包内的 `experiments/continual-*` 会回到原位置；元数据留在仓库根的 `__moltweave_evidence__/`。恢复前应确认目标目录中的已有证据是否就是要恢复的同一批文件。SHA256 证明字节一致性，不替代发布者身份或实验结论的可信度判断。

## 流式与确定性边界

原始大文件按块扫描、哈希和压缩，不整文件加载，不创建 Base64 大副本。仅文件路径/状态列表与有上限的清单占用额外内存；单个清单上限 64 MiB、条目上限 100,000。校验不把原始模型请求读入大字符串。

文件内容与相对路径不变时，tar 成员固定排序，uid/gid、所有者名称、时间、模式固定，gzip 文件名为空且 mtime 为 0；更改原始文件的 mtime 或模式不会改变生成包的内容。原始文件字节不会因此改写。压缩字节的复现还受 Python/zlib 实现影响，跨工具链应以已发布的 archive SHA256 和逐文件清单为准。

微型测试运行方式：

```bash
PYTHONPATH=src python3 -W error::ResourceWarning \
  -m unittest discover -s tests -p test_package_v02_evidence.py -v
```

测试只创建临时小目录，覆盖字节恢复、确定性、边界、密钥、源变化、篡改及独立验证。它们没有扫描、打包或验证正式运行中的数 GB 证据，也不证明最终发布包已经成功生成。
